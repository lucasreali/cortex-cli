LazyCodeIndex deliberately does not cache a failed reconcile, so the next call retries it. That is exactly why the failure path has to close its own connection: nothing holds the handle afterwards, dispose() can never reach it, and a store that keeps failing leaked another code.db connection on every attempt — measured at two descriptors per call.

The open now sits in a try whose catch closes the database and rethrows. The success path is unchanged: the caller owns the connection and dispose() closes it.
