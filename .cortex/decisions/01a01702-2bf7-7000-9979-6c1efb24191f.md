The ~300 MB of q8 weights used to be fetched inside the first embed request, under DEFAULT_EMBED_TIMEOUT_MS (30 s) with disposingOnTimeout killing the worker. On any link slower than roughly 10 MB/s the download was SIGTERM'd, the partial fetch discarded, and the next invocation started from zero — embedding was not slow on that machine, it was impossible, and no message mentioned a download. The daemon repeated it once per request at 60 s.

A worker fetching a model is not a wedged worker, and the deadline that catches the second must never be the budget the first has to finish inside. Acquisition is now its own step: `cortex embed --fetch-model` runs with no deadline at all and skips app/runtime entirely, because which model is on this disk is a fact about the machine, not about a project. The implicit path is no longer unrecoverable either — embedDeadlineMs swaps the inference deadline for MODEL_ACQUISITION_TIMEOUT_MS (15 min) while the model is not resident, at every site that applies one: the queue, embed-all and the daemon. It stays bounded, so a download that is genuinely stuck is still reported.

Rejected: an unbounded implicit deadline (a hung worker would then wedge a background embed forever) and a `loading` phase over NDJSON (it would push a protocol change through the ledger and the daemon's own socket protocol, for a signal the filesystem already carries).
