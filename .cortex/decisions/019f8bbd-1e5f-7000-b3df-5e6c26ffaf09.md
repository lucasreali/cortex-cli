Um único registro MCP user-wide serve todos os repos com .cortex/. As quatro tools ganharam projectPath opcional (src/mcp/tools/project-scope.ts); o RuntimeRegistry (src/mcp/runtime-registry.ts) re-resolve o .cortex/ mais próximo por walk-up A CADA chamada e cacheia o runtime pela raiz RESOLVIDA, nunca pelo path de entrada — cachear o input pinaria a primeira resolução e ignoraria um projeto que ganha store próprio depois (lição do codegraph #926). Sem projeto default (servidor iniciado fora de projeto inicializado) o campo vira obrigatório no schema — canal de alta saliência, codegraph #993. Path não inicializado retorna payload de sucesso {status: not_initialized, guidance} em vez de isError, para o agente não aprender que o toolset está quebrado (antecipa o item 3). serve --mcp deixou de auto-criar .cortex/; init é sempre explícito. Rejeitado: descarte por ociosidade de runtimes — o GemmaProvider já faz spawn lazy do worker e o mata após 5 min ocioso, então o cache por raiz só segura um handle SQLite. Config isolada por raiz: cada runtime pina o model_id do próprio .cortex/config.
