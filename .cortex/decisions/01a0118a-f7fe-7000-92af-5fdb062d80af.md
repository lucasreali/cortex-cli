anchors is keyed by (node_id, file_path, symbol) and nothing deduplicated on the way in, so a file listing the same anchor twice violated the primary key inside the reconcile transaction and took down every command — cortex doctor included, which is the tool that exists to diagnose exactly this. The file arrives by git pull, by a merge that duplicates a list entry, or by a hand edit: decision files are the committed, human-readable product, so this is ordinary input.

uniqueAnchors collapses duplicates at both boundaries: the save path, because a decision file is immutable and the duplicate must never reach disk, and the parse path, because a file that arrived duplicated cannot be rewritten. Deliberately chosen over reporting the file as malformed, which the pre-release review proposed: a repeated anchor carries nothing the first one does not, and marking the file unusable would drop a perfectly good decision out of search over punctuation. The key is the (path, symbol) pair rather than the joined 'path#symbol' text, because a path may legitimately contain a hash and the pair is what the primary key guards. This is not normalization — an anchor is still stored exactly as written.
