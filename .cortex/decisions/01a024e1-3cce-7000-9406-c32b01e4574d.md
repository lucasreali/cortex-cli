The release tarball held exactly one member while the binary bundles twelve third-party packages, one of them Apache-2.0 (transformers.js), whose §4 requires the license text and attribution to travel with the redistributed work. Each tarball now carries LICENSE and THIRD-PARTY-NOTICES.md beside cortex.

The package list is derived per target from that target's own `main.js.map`, not from the dependency graph and not from a hand-kept list. The graph over-lists — 149 packages install, 12 reach the binary — and a hand-kept list under-lists the first time an import changes. Deriving from the sourcemap means a tarball can never name a package the binary beside it does not contain.

A `type: "file"` asset is copied whole and leaves no sourcemap entry, so onnxruntime-web's WASM backend would be redistributed unnamed. Those packages are read off this repo's own `from "..node_modules/<pkg>/.."` imports and unioned in.

A package that declares a license but ships no text (both ONNX Runtime packages) is a build failure unless its text is vendored under scripts/licenses/<pkg>.txt. Degrading to "SPDX id plus a URL" was rejected: it makes a missing notice silent, and vendoring should be a reviewed act.

The pure part lives in scripts/notices.ts so it can be tested; a `@scripts/*` tsconfig alias was added for that, mirroring `@tests/*`.
