upsertTomlTable located the cortex table with an exact whole-line search, so a trailing space, a trailing comment, `[ mcp_servers.cortex ]`, a quoted key segment and an inline `mcp_servers = { cortex = ... }` all missed — and on a miss it appended a second definition. TOML forbids defining a table twice, so the result was not a duplicate server, it was a ~/.codex/config.toml that stops parsing entirely, taking every other MCP server and every other setting with it, reported as a green "updated" line.

The fix splits the two jobs the line search was doing. Bun.TOML.parse decides whether the entry is already defined, in any spelling, including forms no line search could see. The line search only guesses where to splice, so it stays deliberately simple: it does not decode string escapes and it stops at any header it cannot read. The spliced result is then parsed back and deep-compared against the document that went in, with only the cortex entry replaced. A guess that was wrong fails that comparison and the write is refused with a reason, so the worst outcome is a config left untouched and a non-zero exit, never a corrupted one.

That one check subsumes every exotic shape without enumerating it: an mcp_servers that is a scalar, an inline table a header cannot extend, a dotted root key, an array-of-tables — each makes the candidate fail to parse and each is refused with the same message.

Rejected: a full parse-and-serialize round trip. Simpler, and it would rewrite the user's comments and formatting on every install. The splice is what keeps the rest of the file byte-for-byte.

The outcome type is now a single skipped action carrying a reason, shared with the JSON writer, instead of a skipped-unreadable constant the caller had to translate into a message.
