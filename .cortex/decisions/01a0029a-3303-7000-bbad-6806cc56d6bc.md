CLAUDE.md is prescriptive — it names directories, files, exported symbols, SQL tables, MCP tool names and hidden CLI commands — and nothing proved those names still existed; the doc had already drifted once about install.sh's detect_suffix. tests/docs/claude-md.test.ts now extracts every inline-code span from CLAUDE.md and checks it by shape: path-shaped spans must resolve (span, src/span, span.ts, src/span.ts, then a src/**/*.ts basename lookup), kebab-shaped spans must have a file under src/cli/commands/, and multi-word identifiers (PascalCase, SCREAMING_SNAKE, camelCase, lower_snake) must appear as whole words in a corpus of src/**/*.{ts,sql}, scripts/*.ts and install.sh.

Presence in a text corpus, not an export lookup: the names cited are of four kinds — TS exports, SQL tables, MCP tool names that exist only as string literals, and a shell function — and one uniform check covers all four without a per-span kind map, which would be a second registry to maintain. The corpus strips comments and excludes tests/, so a name surviving only in a stale comment or a fixture does not count, and it never reads gitignored state (decisions.db, code.db, coverage/) which exists locally but not in a fresh clone.

Command spans are tokenized on whitespace for the path pass only: 'bun src/cli/main.ts <command>' is the doc's only mention of the dispatch table's full path, and a bare 'main.ts' would otherwise be rescued by the daemon's main.ts. Identifiers are not tokenized — splitting prose would manufacture junk.

Spans that fit no shape are ignored (prose like 'bun test', 'status', 'await'), so a minimum-match floor guards the extractor itself: a regex that silently matched nothing would make every other assertion vacuous. Names that deliberately do not exist go in an exemption map with their reason (decisions.db, code.db, lcov.info are derived artifacts; content_sha is a column CLAUDE.md says it does not have yet), checked in both directions like scripts/coverage-audit.ts: an exemption that stops being cited fails, and so does one that starts resolving.

All logic stays inline in the .test.ts file because bunfig's coverageSkipTestFiles only exempts *.test.ts — a helper under tests/ would be instrumented and owe 100% coverage on its own.
