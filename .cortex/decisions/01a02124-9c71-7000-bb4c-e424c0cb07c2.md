Staleness was decided by (size, mtime), with the content hash only a post-hoc shortcut once a file had already been re-read. Both halves of that pair are forgeable by an ordinary restore: `cp -p`, `tar -x`, `rsync -t` and most CI cache restores land new content under the recorded mtime, and a same-length edit keeps the size. The index then served symbols that no longer exist and doctor reported "in sync". No userspace call can set an inode's change time, so `ctime` is the one half a restore cannot forge; it joins the triple in `files`, in `isUnchanged` and therefore in `computeDrift`, which has to agree with it or doctor calls a stale index clean. A ctime that moves without the content moving costs one read and a `touchFile`; the reverse costs correctness.

Separately, `dist` and `build` were excluded by path segment whoever produced the listing, so a tracked `src/build/pipeline.ts` was never indexed and nothing reported it — `computeDrift` uses the same filter. A git listing already came through `--exclude-standard`, which applied the project's own `.gitignore`, the authority on what is generated here; the guess now applies to the fallback directory walk alone. `node_modules`, `.git` and the store's own directory are dropped either way.

Replaces the original incremental-index decision.
