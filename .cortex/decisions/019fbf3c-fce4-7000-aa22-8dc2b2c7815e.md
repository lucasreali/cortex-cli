installBinary stages the new binary next to the target as <target>.<pid>.partial, chmods it 755, runs it once with --version and requires the expected version, and only then renames it over the running executable. The running process cannot be written into (ETXTBSY) but rename is safe on POSIX: it keeps the inode it started from. Staging next to the target keeps the rename on one filesystem. The probe is what makes a wrong-architecture download harmless — posix_spawn raises ENOEXEC rather than returning an exit code, so the spawn is wrapped and any failure aborts with the working binary still in place. The asset's sha256 from checksums.txt is verified before the archive is even opened, never weaker than install.sh. Concurrent upgrades need no lock: staging names are pid-scoped and both renames are atomic.
