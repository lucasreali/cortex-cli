migrate() and migrateCode() now read MAX(id) from _migrations and throw when it exceeds the newest migration this binary knows, naming the store and the fix. Before this, nothing asked: an older cortex opened a newer store and wrote to it. doctor warned, but a warning does not stop log, search, save_decision or the git hook from writing to a schema they do not know.

It is latent today because every migration so far only widened a CHECK, and that is exactly why refusing is right: the damage would be silent — rows the binary cannot represent, read back through columns it never saw — rather than a loud failure someone would notice. The guard costs one query. The consequence accepted is that doctor fails too instead of diagnosing; its message names the store, the two versions and 'run: cortex upgrade', which is the whole diagnosis anyway.
