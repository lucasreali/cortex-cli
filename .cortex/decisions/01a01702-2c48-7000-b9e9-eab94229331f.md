SemanticSearch's vector cache was invalidated only by in-process events — the queue's onEmbedded hook, a reconcile that touched something, save_decision — while the design deliberately pushes embedding out of process: the git hook spawns `cortex embed --missing` detached, and CLAUDE.md tells users to run it by hand. Neither can call invalidate() on a running MCP server, so an agent saved five decisions, the user committed, the hook embedded them, and for the rest of that editor session semantic search answered from FTS and reported them as no match.

SQLite bumps PRAGMA data_version only when another connection commits to the file — never for this connection's own writes — which is exactly the case the hooks cannot see and nothing else. So loadCache compares it and re-reads when it moved. The existing in-process invalidation keeps its meaning, a count- or rowid-based fingerprint would have missed an in-place rebuild, and the check costs one pragma per search.
