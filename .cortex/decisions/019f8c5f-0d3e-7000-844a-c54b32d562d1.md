Cada sessão MCP subia seu próprio subprocess com o EmbeddingGemma-300m, duplicando um model load pesado por sessão concorrente. Agora um daemon por usuário (não por projeto: o modelo é global, N repos compartilham) é dono de um único GemmaProvider e serve o MESMO protocolo NDJSON do worker por socket Unix em ~/.cortex/daemon/<model>.sock. Por conexão: hello versionado (versão da CLI + model_id; mismatch → cliente desiste sem matar o daemon). Eleição por lock 'wx' cujo clear exige pid comprovadamente morto; colheita por refcount de clientes + idle timeout de 5 min (CORTEX_DAEMON_IDLE_TIMEOUT_MS); worker travado não trava o daemon (timeout de 60s por request com dispose/respawn do provider interno). O cliente SharedEmbeddingProvider decora o GemmaProvider: proba o socket, spawna o daemon destacado se preciso e degrada para o worker privado em qualquer falha — compartilhar é otimização, nunca dependência (opt-out CORTEX_NO_DAEMON=1). Escopo: só o caminho MCP (RuntimeRegistry); comandos CLI one-shot mantêm worker próprio. Rejeitado: daemon por projeto no estilo codegraph com proxy MCP completo — o ativo compartilhável do cortex é apenas o worker de embedding, então o daemon fala o protocolo do worker e dispensa proxy de sessão MCP. Medido no repo real: 1ª sessão fria 4.1s (spawn + model load + embed), 2ª sessão 424ms reusando o mesmo daemon (mesmo pid).
