Cada decisão passa a ser um arquivo imutável em .cortex/decisions/<uuid7>.md, versionado junto do código; decisions.db e code.db são caches derivados e ficam gitignorados. Isso resolve o problema do fantasma (decisão salva num branch que nunca mergeia ficava ativa para sempre em todos os branches, inclusive injetada passivamente pelo prompt-hook) e elimina o binário immergível no git, cujos conflitos só eram resolvíveis descartando as decisões de um dos lados, além do risco de corrupção quando git checkout troca o inode sob a conexão SQLite aberta que o RuntimeRegistry mantém. O id é o nome do arquivo (UUIDv7), então dois branches nunca colidem e o git faz merge sozinho. Rejeitado: tabela de branch (squash/rebase destroem o commit de origem, então nem nome de branch nem 'merged into X' respondem 'isso entrou?'), embeddings dentro do arquivo (o vectorLeg precisa do modelo local para embedar a query, então vetor guardado é peso morto numa máquina sem modelo, e ~1.4KB de base64 destruiria o diff revisável), NDJSON append-only com merge=union (corpo vira linha escapada ilegível) e merge driver customizado para o .db (exige configuração em todo clone, morre em CI).
