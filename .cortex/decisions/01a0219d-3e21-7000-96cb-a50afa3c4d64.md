Two small contract repairs that the audit found together.

runGit checked only result.exitCode, but Bun.spawnSync itself throws before there is one: with no git on PATH every command died with "Executable not found in $PATH: git", and getRepoRoot on a cwd that no longer exists threw ENOENT. Both are exactly the cases the callers' null fallbacks were written for — runtime.ts's `?? resolve(cwd)` was unreachable in the one situation it existed for — so the spawn is wrapped and both are answered like any other non-zero exit. One try/catch restores the documented "none of them throw" for all five accessors. The regression test for the missing binary has to be a subprocess: Bun does not resolve the executable through a PATH the running process reassigns.

CONFLICTS_WITH is stored symmetrically and was surfaced only by get_context — the one surface a reader consults instead of asking about impact. get_impact and `cortex impact` are precisely what you call before contradicting a decision, so DecisionImpact now carries conflicts (id and title, resolved through listConflictPartners from either endpoint, present decisions only) and both renderers show it. It is not a fourth walk: one query for the root id, no depth, no code index.
