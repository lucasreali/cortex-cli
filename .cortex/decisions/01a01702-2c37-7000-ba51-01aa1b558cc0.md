The degradation ladder is shared daemon → private worker → pure FTS, but the fallback existed only for the connect failure. Once a connection was established, a daemon that died mid-request — including one killed by cortex's own upgrade path — propagated ledger.rejectAll straight out of sendToDaemon, so the request skipped the middle rung: a query degraded to FTS and a save logged "embedding left pending" and stayed FTS-only.

Distinguishing the two failures by error message would be brittle, and the connection already knows: client.ts sets state.open = false before rejecting on a disconnect or a close, while a model error the daemon returned settles through the ledger with the link still open. So `connection.alive` is the discriminator — alive means the daemon ran the model and returned a verdict the private worker would only repeat, and that one is rethrown. A dead link is retried on the direct provider, once.
