Whether the weights are here cannot be read off the cache directory: transformers.js creates it before the first byte lands, so a run killed mid-download leaves a directory that looks finished — which is exactly the state the previous doctor check reported as "model downloaded". Checking for the weight file instead would couple us to transformers.js's dtype-dependent file naming.

So the worker stamps `.cortex-model-resident` inside the model directory once the extractor has actually loaded, which is the only moment the answer is certainly yes. It lives inside that directory so deleting the model deletes the verdict with it, and marking is best effort: a read-only or full models directory costs the next run its deadline shortcut, never the embedding that just succeeded.

The fact is exposed as an optional EmbeddingProvider.modelResident(), and a provider that does not answer is taken at the configured deadline — only the process that would spawn the download knows there is one to wait for, so a fake or a stub never silently inherits a 15-minute budget. doctor reports all three states: downloaded, cache present but unconfirmed, absent.
