v0.4.0 was tagged and then nineteen commits — five of them user-visible features — landed on top of it while package.json still said 0.4.0. CORTEX_VERSION derives from package.json, so a binary built from HEAD reported a version belonging to a materially different program, and BENCHMARKS.md was already stamped "with cortex 0.4.0" for a newer corpus. Nothing anywhere had to agree with package.json, which is why nothing did.

tests/docs/release-paperwork.test.ts now asserts that the version in package.json appears as a CHANGELOG section with a compare link, as the `CORTEX_VERSION=` and `asset=` pins in the README's install examples, and in BENCHMARKS.md's generation stamp. The invariant holds continuously, not only at release time: between releases package.json still names the last released version, and all three still have to agree with it.

The release workflow's tag-vs-package.json assert stays where it was; it catches the tag, this catches everything the tag is supposed to mean.
