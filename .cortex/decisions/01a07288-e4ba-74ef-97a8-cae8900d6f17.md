Git for Windows runs hooks through the sh it bundles, and that shell reads a backslash as an escape rather than a path separator. A drive-letter path spelled with forward slashes — C:/Users/dev/.../cortex.exe — is the one form both that shell and the Win32 API accept.

The conversion happens in selfCommand, the single producer of the words a hook pins, rather than in buildHookBody or in every site that quotes a path. That keeps isShellSafeCommandWord a pure judge of a word: it now accepts a drive letter as a root beside the empty root an absolute POSIX path leaves, and still refuses a backslash outright — so a POSIX file genuinely named "bin\\cortex" is rejected here exactly as before, instead of being silently rewritten into a different path. A root on its own ("" or "C:") names no program and is refused, which is what keeps an empty word from passing the segment check vacuously.

The second half is that a file URL is not a path. new URL(...).pathname hands back a leading slash before the drive letter, which no spawn and no fs call will accept, so selfCommand's entry path, embedWorkerCommand, embedDaemonCommand and scripts/compile.ts's ROOT all go through fileURLToPath. These are the source-checkout spawn paths and the build script — the compiled binary reaches its subcommands by name and never derives a path from a module URL.
