O ImportResolver resolve contra o conjunto de arquivos indexados pelo walker (nunca o filesystem): to_path só aponta para o que existe no índice. provenance 'exact' exige specifier relativo com extensão explícita batendo direto num arquivo indexado; todo o resto (extensão omitida com trials ts/tsx/js/jsx/mts/cts/mjs/cjs, diretório→/index.*, remap NodeNext ./x.js→x.ts, aliases e baseUrl) é 'heuristic'. tsconfig.json é lido com o loader JSONC nativo do Bun — import(path, { with: { type: 'jsonc' } }) — aceitando comentários e vírgulas finais sem parser próprio; tsconfig ausente/malformado degrada para zero aliases, nunca lança. paths sem baseUrl resolvem relativo ao diretório do tsconfig (comportamento TS5); alias nunca é 'exact'. Specifier vazio, absoluto, escapando da raiz ou npm/builtin → to_path NULL. Taxa medida no próprio repo em 2026-07-21: 162/168 = 96,4% dos imports com intenção resolvível (meta ≥ 85%); os 6 não resolvidos são corretos — imports de .sql (fora do índice de código) e fixtures apontando para arquivos inexistentes. O teste tests/indexer/resolution-rate.test.ts refaz a medição a cada suíte e trava a régua em 85%.
