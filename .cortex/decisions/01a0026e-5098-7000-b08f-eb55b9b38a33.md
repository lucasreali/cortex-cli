cortex install --git-hooks escreve um bloco delimitado por
# cortex-hook-start / # cortex-hook-end em post-commit, post-checkout e
post-merge do repositório atual. post-merge entra porque um git pull que
faz fast-forward não dispara nenhum dos outros dois, e receber decisão de
outra pessoa é exatamente o caso que motivou o item. O bloco é burro de
propósito — um if [ -x ] chamando o subcomando oculto cortex git-hook —
para que toda a decisão (qual evento age, se embeda, se existe store)
fique em TypeScript testado em vez de heredoc de shell. Nunca há exit,
set -e ou set -u no bloco: o usuário pode acrescentar linhas abaixo dele.
O caminho absoluto do binário é fixado na instalação (git roda hook com
PATH mínimo de cliente gráfico e CI) e validado contra uma allowlist de
caracteres por segmento de path antes de ser interpolado.

git-hook é a imagem espelhada do prompt-hook: reconciliar é o trabalho
inteiro, então abre o store read-write — mas só quando decisions.db já
existe, de modo que hook nenhum cria store atrás de um commit. Ele
desvia de app/runtime (que registraria o projeto, poderia reescrever o
config e imprime quando não inicializado), retorna 0 em todo caminho e
dispara embed --missing destacado apenas depois de commit ou merge —
nunca depois de checkout, porque git rebase reexecuta esse hook uma vez
por commit e decisão que volta mantém o vetor.

O diretório de hooks vem do próprio git (rev-parse --git-path hooks), o
que respeita core.hooksPath, husky e worktrees ligados; não há guarda de
worktree porque .cortex/ é gitignored e cada worktree tem store próprio,
então rodar lá é o comportamento correto. Depois de escrever, chmod 0755
é incondicional: writeAtomically renomeia um arquivo temporário novo por
cima do alvo e git ignora hook não executável em silêncio, então sem isso
a segunda instalação desligaria o hook do próprio usuário.

Rejeitado: rodar cortex index no hook (o índice de código continua lazy,
a decisão 019f8aaf-9e54 segue de pé e seu gatilho de reabertura continua
aberto); adicionar um comando cortex uninstall (a remoção é
install --git-hooks --uninstall, dentro do instalador que já existe);
appendar o bloco em hook de outro interpretador — um #!/usr/bin/env
python3 recebe recusa explícita, porque quebrar o commit é justamente o
que esta feature promete nunca fazer.
