Every command that builds a runtime died on a corrupt decisions.db with SQLite's own sentence — "file is not a database" — naming neither the file nor a way out, while the file is a derived cache and the decision markdown under .cortex/decisions/ is the product. withRuntime now catches SQLITE_NOTADB alone (anything else still throws), names the absolute path, says it is a rebuildable cache, and tells the reader to delete it and run `cortex sync`.

It is caught in withRuntime rather than in doctor because the failure is not doctor's: log, why, search, impact, sync and embed all die the same way, and one message serves all of them.

It reports rather than repairs. Deleting a database on a read command is the one action that cannot be taken back if the diagnosis was wrong — a file that is not SQLite could still be something the user wants — so the remedy is printed and the deletion stays the user's.

Depends on the failure reporter, so `doctor --json` gets the same sentence as an object.
