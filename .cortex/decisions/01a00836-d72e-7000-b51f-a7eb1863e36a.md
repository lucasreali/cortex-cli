Backlog item 15: post-commit spawns a detached cortex embed --missing whenever the reconcile leaves vectors pending, and git fires post-commit once per replayed commit, so a fifty-commit rebase that carried never-embedded decisions loaded the embedding model fifty times.

Decided: the hook still reconciles on every replayed commit, but skips the embed while git's sequencer has steps left to run. src/git/replay.ts answers that from the todo file git already maintains — rebase-merge/git-rebase-todo for a rebase on the merge backend, sequencer/todo for a multi-commit cherry-pick or revert — and embedsAfter in src/cli/commands/git-hook.ts consults it.

The measurement that makes this exact, on git 2.53: git rewrites the todo before running post-commit, so it holds only the steps still to come and is empty on the last replayed commit. Skipping while steps remain therefore defers nothing to a later command — the final commit of the replay spawns exactly one embed, which covers everything the whole rebase brought. GIT_REBASE_TODO, which the backlog item suggested, is not exported to post-commit at all; neither is GIT_DIR.

The git directory is found by walking up from the hook's cwd (a .git directory, or the gitdir: pointer a linked worktree and a submodule leave), never by asking git or trusting an inherited GIT_DIR, which names the superproject during submodule work. A checkout that cannot be resolved answers false, which is the old behavior — the guard can only cost an extra embed, never a missing one.

Rejected: installing post-rewrite as a fourth hook to run the embed at the end of the rebase — it stays redundant for the reason already recorded, it would have required every user to reinstall their hooks, and it does not fire for cherry-pick or revert. Also rejected: a lock file coalescing concurrent embeds, which is racy about which process picks up the last commit's decisions where reading the todo is deterministic.

Known gap, accepted: an interactive rebase whose todo ends in exec or break lines still has steps after its last commit, so that replay's embed waits for the next commit or merge. cortex doctor reports the pending count meanwhile.
