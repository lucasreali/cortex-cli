The suite used to write the developer's real ~/.cortex — the tree-sitter grammar was fetched from GitHub into it on every run — inherit their real HOME, so cortex init's harness detection saw whatever agent configs happened to be installed, and leave about 7,000 directories behind in /tmp, one per mkdtemp no afterEach ever cleaned up.

tests/preload.ts now creates one directory per run and points HOME, CORTEX_DAEMON_DIR, CORTEX_PROJECTS_FILE and TMPDIR at it, removing it in a global afterAll registered from the preload itself. Setting TMPDIR is what makes the leak fix systemic rather than a sweep of eighteen files: every mkdtempSync(tmpdir()) call site in tests/ lands inside the run's own directory, so a test that forgets to clean up costs nothing and no future one can reintroduce the leak.

A process exit handler does not work here — bun test does not run them. A global afterAll from a preload does.

Only two things may outlive a run, because re-fetching them per run is not affordable: the grammar (a GitHub download) and the model (hundreds of megabytes). They go to a stable cache of the suite's own under the system temp directory, never the developer's home, and .github/workflows/ci.yml keys that path the way it used to key ~/.cortex/grammars.

Forcing HOME exposed one hidden dependency: a real rebase replays commits with the repository's identity rather than the one passed per git invocation, so tests/git/replay.test.ts had been leaning on the developer's global git config. It configures its own now.

Deliberately not redirected: scripts/compiled-smoke.ts, which is not bun test and exercises the binary against the real per-user cache on purpose.
