The 1 MB cap used to drop a file from the listing entirely, which also dropped it from the resolver's file set: every import pointing at a large generated module resolved to NULL, get_impact under-reported, and doctor reported a low resolution rate with no cause. An oversized file is now listed — the resolver can point an import at it — and recorded as skipped, so the pass never reads or parses it.

That one skip list is what keeps the two halves honest: computeDrift reads it too, so a file the pass will never index is neither new work nor a deletion, and doctor cannot demand a reindex that can never settle. Binary content is the same story one step later: a blob carrying a source extension is detected by its NUL byte after the read, kept as a file row so it stops looking like drift, and never handed to tree-sitter, which spent about a second per such file to return nothing.
