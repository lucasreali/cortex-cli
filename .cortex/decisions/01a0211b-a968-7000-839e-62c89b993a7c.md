RuntimeRegistry held a plain Map with no cap, no TTL and no eviction: entries were released only by dispose() at shutdown, and each holds an open decisions.db, a lazily opened code.db, an embedding provider and the project's resident vector set. Twenty-five projects took one server from 13 to 94 open descriptors and it stayed there; at a few hundred projects the next Database or Bun.spawn fails with EMFILE and every later tool call returns isError.

The cache is now LeasedRuntimes: an LRU capped at 8 entries that disposes what it evicts. Eviction is only safe because of the lease — withRuntime(projectPath, use) counts a runtime as in use for the duration of the handler and releases it in a finally, and only entries with zero leases are eligible victims, so a runtime a concurrent tool call is querying is never closed underneath it. scopedToProject calls withRuntime instead of resolve, which also moved project resolution inside the try: a store that throws on open is now a fault of that call rather than an uncaught throw.

The fan-out is deliberately not admitted into this cache at all — it opens, queries and closes a ProjectReader — so a single sweep can never fill it.

After dispose() the registry is closed: a late tool call answers with guidance saying the server is shutting down, instead of re-opening a runtime nobody will ever close. Shutdown drains every project's embed queue at once rather than one after another, and every await on that path is bounded by 5 s, so a supervisor that SIGKILLs at 10 s cannot defeat the drain the code exists to guarantee.
