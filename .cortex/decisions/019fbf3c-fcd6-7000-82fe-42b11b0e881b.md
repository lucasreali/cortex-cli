cortex upgrade resolves which release asset to download from a value baked in by scripts/compile.ts through Bun.build's define (process.env.CORTEX_BUILD_TARGET), not from runtime detection. A running binary cannot tell which libc it was linked against, nor that it was built for a baseline CPU, so a musl or linux-x64-baseline install would silently upgrade itself to an incompatible variant. package-release.ts already knows the suffix for every cross-compiled target and passes it through. Verified that define survives --compile: the baked literal wins even over a runtime env var. Locally built binaries bake nothing and fall back to describing their host (platform, arch, musl), which is why install.sh's detect_suffix and src/release/target.ts must keep agreeing. Accepted trade-off: a baseline install keeps upgrading to baseline even on an AVX2 machine; switching variants means re-running install.sh.
