reasonToLeaveAlone refused binary hooks and foreign interpreters, but a POSIX-sh hook ending in `exit 0` or `exec ...` — the shape husky and every hook generator writes — was accepted and the cortex block went below it, where the shell never arrives. Three green lines, and decisions silently stop reconciling on commit.

Refusing every such hook would be the wrong trade because that ending is so common, so the block is placed immediately above the file's final statement when that statement is an unindented `exit` or `exec` — which is where a person would have written it by hand. The placement is unconditional for that shape, so it is idempotent: a re-run reproduces the same bytes and reports unchanged, and a block an older cortex stranded below the terminator is lifted back above it. An `exit` anywhere else is a branch this cannot read, so a hook containing one is refused by name when the block is absent, and left exactly as its author arranged it when the block is already installed.

Separately, installOne chmodded 0755 unconditionally after every write. writeAtomically already copies the destination's mode onto the staging file, so the chmod existed only for a hook we created — and it published a hook the user had deliberately kept at 0700 to their group and to everyone else. It now mirrors `chmod +x`: an execute bit wherever a read bit already is, and no chmod at all when the mode already says executable. A file cortex created has no mode to keep and still gets 0755, because git silently skips a hook it cannot execute.
