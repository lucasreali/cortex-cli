createDecisionSchema counted untrimmed characters while decision-file.ts trims the body and rejects an empty one, so the two boundaries disagreed: a body of 40 spaces saved successfully, returned an id, and was malformed on disk from that moment on — and since a fresh clone rebuilds the store from the files, the decision was lost entirely there.

z.string().trim().min(30) measures what the file will actually hold, and stores it trimmed, so the save tool and the parser now agree by construction rather than by coincidence. The rule generalizes: any authoring minimum in the schema has to be stated over the value the file format will keep, not the value the caller sent.
