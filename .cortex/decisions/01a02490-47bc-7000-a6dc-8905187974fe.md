install.sh published the download with `mv -f "$tmp/cortex" "$INSTALL_DIR/cortex"`. mktemp lands in tmpfs while $INSTALL_DIR is normally on the root filesystem, so that mv is not a rename: coreutils unlinks the destination and copies ~60 MB into a fresh inode. For the length of that copy the installed cortex is a truncated but already-executable ELF, and Ctrl-C in that window leaves a broken binary that `cortex upgrade` cannot repair, because it is the broken binary. Nothing checked the result ran, either.

It now takes the same shape as src/release/installer.ts: extract to tmp, copy to `$INSTALL_DIR/cortex.$$.partial`, chmod, run `--version` and require it to report the version being installed, then `mv` within the directory — a real rename. The staging file is in the EXIT/INT/TERM trap, so an interrupt or a refusal leaves the previously installed binary byte-for-byte intact.

Two smaller things in the same file. Every curl now carries `--proto =https --proto-redir =https`: -L would otherwise follow a downgrade to plain http, and checksums.txt travels the same channel it is meant to secure. And the latest-release lookup ran inside a command substitution under `set -eu`, so a curl that failed exited the whole script with no message; it now dies with one.

The install path is covered by a test that puts a stub curl on PATH serving a local fixture directory, which is what makes the script's install() reachable without the network.
