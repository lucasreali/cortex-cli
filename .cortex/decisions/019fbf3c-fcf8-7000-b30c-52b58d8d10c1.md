The embedding daemon socket is keyed by model id, not by version, so after an upgrade the old daemon keeps the socket and the handshake rejects it on the version mismatch. A rejected probe deliberately does not spawn a replacement (it would lose the lock race to the live holder), so every session would degrade to a private worker until the old daemon's idle timeout expired. The upgrade command now reads the daemon lock and sends SIGTERM after a successful replacement; daemon/main.ts already handles the signal and removes the socket. Killing it is safe because of the degradation ladder: an in-flight request falls back to a private worker and the query path's timeouts guarantee FTS answers. stopDaemon signals without a liveness check first, so a dead pid simply returns false — which also makes the failure branch testable without signalling a foreign process.
