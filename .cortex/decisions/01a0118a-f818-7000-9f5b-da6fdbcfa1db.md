The guard that skips the full reconcile counted ids: no arriving, absent or restored files meant nothing to do. But an unparseable file is never inserted, so its id stays in 'arriving' for as long as the file sits there — and the guard therefore never fired again. Every process that builds a runtime, MCP read tools included, ran clearVersionedEdges plus a full re-insert of the whole edge table; a second non-full pass was measured deleting a DEPENDS_ON edge inserted between the two calls.

The cheap path now parses just the arriving ids and asks whether any of them are usable. That is what it pays to stay cheap: when nothing is arriving it costs nothing, and the malformed files it did read are still reported, so an unreadable arrival is named on the first pass exactly as before. The whole-directory parse stays where it was, on the full path.
