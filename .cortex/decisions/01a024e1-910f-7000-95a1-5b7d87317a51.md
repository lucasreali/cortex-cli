The job that ran the tests was a different checkout from the job that compiled the published artifacts, so "the compiled binary smoke test passed" was a claim about a binary nobody would ever download.

After packaging, the release job unpacks dist/release/cortex-$TAG-linux-x64.tar.gz, asserts LICENSE and THIRD-PARTY-NOTICES.md are inside it, and drives that binary end to end. scripts/compiled-smoke.ts takes CORTEX_SMOKE_BINARY and skips its own compile when it is set; unset, it behaves exactly as before, so CI and a developer running `bun run smoke:compiled` are unaffected.

Making the two jobs share an artifact instead was rejected: the gate must be able to run on a branch with no packaging step, and uploading a 116 MB binary between jobs costs more than unpacking the tarball that already exists.

linux-x64 is the only target smoked here because it is the runner's own platform; darwin-arm64 is covered by verify-darwin, which downloads the published release.
