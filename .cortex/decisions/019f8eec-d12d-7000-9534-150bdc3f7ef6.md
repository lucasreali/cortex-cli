dist/cortex (~117 MB) is produced by scripts/build.ts via Bun.build --compile; bun run smoke:compiled proves it end to end. Four constraints shaped the design. (1) Subprocess entrypoints: a compiled binary cannot execute loose .ts files, so the embedding worker and daemon became hidden CLI subcommands (embed-worker/embed-daemon); src/embedding/subprocess-command.ts picks between re-invoking process.execPath (compiled, detected by the $bunfs module prefix) and spawning the source files (checkout). transformers loading in worker.ts became lazy so importing it from the CLI graph stays cheap. (2) transformers.js's node build statically imports sharp and onnxruntime-node — fatal without node_modules — so the build stubs them with a plugin; runtime never touches them because process.release.name='bun' pins the WASM backend. (3) onnxruntime loads ort-wasm-simd-threaded.asyncify.{mjs,wasm} and dynamically imports the .mjs, which requires a real on-disk file: both are embedded with type:'file' imports and extracted once to ~/.cortex/onnxruntime/<content-hash>/ (atomic rename, idempotent). (4) web-tree-sitter's Parser.init gets locateFile pointing at the embedded wasm. Rejected: shipping worker/daemon as separate binaries (breaks the single-file story) and bundling the transformers web build (would diverge from the dogfooded node-build runtime). Install script deferred until there are external users.
