The README's measurements had all drifted from the commands it tells the reader to run: the retrieval claim said 0.978/1.000 where `bun run eval:search` reported 0.896/0.917, and the benchmark table disagreed with the generated BENCHMARKS.md on every cell while linking to it two paragraphs later. Prose review had not caught either, because nothing in the suite read the README.

So the README is treated as a derived document and gated like one. `tests/docs/readme.test.ts` asserts, against the sources that generate the numbers: the `## CLI` block documents every command `cortex --help` advertises and no hidden one, carrying every flag and placeholder from `USAGE`; the benchmark table equals BENCHMARKS.md cell for cell and both name the same corpus size; the stated evaluation-case count equals `GROUND_TRUTH.length`; and the manual MCP snippet parses as strict JSON and names the command `resolveServerSpec` would write. Each check was verified by mutation — reintroducing the original defect fails the suite.

Rejected: deleting the numbers from the README to end the drift. The measurements are the pitch of a tool whose claim is measurement, and a reader who has to run three commands to see them will not. Rejected too: generating the README section from the benchmark command, which would put a marker fence in the document people read first for one table.

The consequence is a rule, not a hope: regenerating BENCHMARKS.md now fails the suite until the README's copy is updated in the same commit.
