`TsconfigAliases.load` read exactly one file and one key: `<repoRoot>/tsconfig.json`. Nx, Turborepo, Angular and most `@/*` layouts keep `baseUrl` and `paths` in a shared base config the root one extends, so for those repositories every aliased import resolved to NULL — get_impact returned no code impact at all and doctor could only say "below 85%" with no actionable cause. A silent, whole-repository capability loss on the most common enterprise layout.

The chain is now followed: `extends` as a string or an array, relative, absolute, or a bare specifier resolved upward through node_modules the way node would (falling back to the package's own tsconfig.json). Layers are collected depth-first and most-derived-first, so "the nearest layer that spells this key wins" is a `find` — which is how tsc merges compilerOptions — and a visited set makes a cycle terminate. A later entry of an `extends` array overrides an earlier one, so the array is walked backwards.

Two path rules carry the meaning. `baseUrl` is resolved against the directory of the file that declared it, not the repo root. `paths` targets are resolved against `baseUrl` when the effective config has one and against the directory of the file that spelled the map otherwise (TypeScript 4.1 semantics) — the only reading that lets one published base config serve every package that extends it.

The file is read with readFileSync + Bun.JSONC rather than `await import(..., { with: { type: "jsonc" } })`: the ESM cache is keyed by path, so an edited tsconfig kept its old aliases for the life of the process, which for the MCP server means until a restart. Reading it synchronously also let `TsconfigAliases.load` and `ImportResolver.create` drop their async: an extends chain is a handful of small files read once per pass, beside a stat of every source file in the repository, and the walk it feeds is synchronous throughout.

Per-package tsconfig.json files are still not read — the resolver holds one alias set for the whole repository. That is the next step if a monorepo needs different aliases per package.
