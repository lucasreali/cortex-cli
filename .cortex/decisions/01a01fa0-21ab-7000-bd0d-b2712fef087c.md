prompt-hook interpolated title, module and body straight into its context fence, so a decision file whose body carried the closing tag put everything after it outside the fence, as top-level prompt text, on every prompt in that repository — and the keyword gate is declared by the same file, so the payload could be aimed at common words. A merged pull request adding one markdown file was the whole exploit.

The fix is one recipe in src/support/prompt-fence.ts, shared by two directories that cannot import each other: fenceSafe escapes both angle brackets out of every string a decision file contributes, and truncate runs after the escape so a cut cannot reassemble a tag out of the characters it leaves behind. Every field from the file is escaped, the ten-character date included — one rule a reader can check beats four per-field arguments about which length is too short to matter.

breaksPromptFence is the reconcile-time half and it only matches the closing tag: the opening one never terminated anything, and matching it would fire on every decision that merely documents this. A file that matches is named in ReconcileReport.fenceBreaking and warned about by doctor, and still imported. Rejected: treating it as malformed — the escape already made it harmless, dropping a decision off the branch over a string is the larger damage, and a decision explaining this feature would refuse itself. Also rejected: capping the list the way malformed files are capped. Unreadable files arrive in bulk from a corrupt checkout and share a cause worth inferring from the first five; each of these is a separate deliberate act to look at.

Two smaller things in the same hook. Its stdin is now bounded in time (2 s) and size: the caller writes one JSON object and closes, so a pipe held open is never a slow prompt, and `( sleep 30 ) | cortex prompt-hook` used to hang for as long as the writer held it. And read-only to SQLite is not read-only to the filesystem — reading a WAL database still creates -shm — so a .cortex the user cannot write is a store this hook cannot open; it exits 0 in silence like every other failure path, deliberately, because a hook running in front of every prompt has no channel to complain on that would not become noise on every prompt.
