The indexer loaded only tree-sitter-tsx.wasm and fed it every extension. TSX and TS are separate grammars precisely because `<T>expr` is a type assertion in .ts and a JSX element in .tsx: parsed with TSX, one assertion in a .ts file becomes an ERROR node that swallows the rest of the file, so every symbol after it disappears with no diagnostic. `ensureGrammars` now caches both (same pinned-release, sha256-verified mechanism) and `TsxExtractor.extract` takes the walker's `lang`: .ts gets the TypeScript grammar, everything else the TSX one — .js and .jsx carry JSX far too often to risk the other way round.

`rootNode.hasError` is recorded per file (`IndexedFile.hasError`, files.has_error) rather than thrown: one unparsable file is still a file, and the imports before the break are still true. What changes is what may be claimed about it. Anchor grading now returns `file_only` instead of `unresolved` for a symbol absent from a file the grammar could not read end to end — the symbols of such a file are a prefix, never an inventory, so "absent" there is a fact about the extractor, not about the code. doctor reports the count.

The class keeps the name TsxExtractor even though it is no longer TSX-only: decisions already in .cortex/decisions/ anchor symbols in src/indexer/tsx-extractor.ts, and an anchor is immutable once written.
