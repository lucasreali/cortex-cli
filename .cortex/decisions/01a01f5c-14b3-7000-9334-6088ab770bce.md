install.sh and src/release/target.ts pick the asset separately — one for install, one for upgrade — and a CI job asserts they agree on the runner. They disagreed on a host with no readable /proc/cpuinfo: `grep -q avx2 /proc/cpuinfo 2>/dev/null` exits 2 when the file is absent, so the shell asked for linux-x64-baseline, while supportsAvx2 returned true and asked for linux-x64. The comment claimed they agreed and a test pinned the divergence; the CI parity job could never observe it, because it only runs where /proc/cpuinfo exists.

TypeScript now answers an unreadable cpuinfo the way the shell does, and that is also the safe direction: the baseline build runs on either CPU, where the AVX2 build meets a machine without AVX2 as an illegal instruction. readFileSync in a try replaces the existsSync check, so an unreadable file and an absent one are the same answer.

The libc probe had the mirror-image problem: Bun.spawnSync throws when there is no ldd to spawn, where the shell reads the failed command as "not musl" and carries on. It is caught, and the probe is handed only PATH — which is what a probe needs, and what lets a test stand in for a host with no ldd, since a subprocess otherwise inherits the environment this process started with rather than the one it has now.
