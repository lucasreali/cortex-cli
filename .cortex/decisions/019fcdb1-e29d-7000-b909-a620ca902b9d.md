cortex install detects coding-agent harnesses (Claude Code, Codex CLI, Cursor, Gemini CLI) by cheap existsSync probes on their user config dirs and writes only the cortex MCP entry into each user-scope config (~/.claude.json, ~/.codex/config.toml, ~/.cursor/mcp.json, ~/.gemini/settings.json), preserving sibling servers and refusing to touch unparseable files (tri-state read, no backup-and-overwrite). Codex TOML is edited by line splice, not a parser, so the rest of the file survives byte-for-byte. MCP registration stays user-wide because one server serves every project; per-project guidance instead lives in marker-fenced (<!-- cortex:begin/end -->) blocks that cortex init upserts into the instruction files of the harnesses actually in use (CLAUDE.md, AGENTS.md shared by Codex/Cursor, GEMINI.md) — project-local by preference, no global instruction files. UX is Bun's confirm() plus --yes/--target; a prompt library dependency was rejected. Pure logic sits in src/install/ (home passed as a parameter, 100% in-process coverage); only the thin command files touch process state. Modeled on codegraph's multi-target installer.
