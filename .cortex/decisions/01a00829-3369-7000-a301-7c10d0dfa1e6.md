The backlog recorded post-rewrite as deliberately deferred, justified by the claim that a rebase fires post-checkout once per replayed commit and that the only remaining gap was a commit --amend. That claim is wrong, and the correction changes the verdict from "deferred" to "redundant".

Measured against git 2.53 with the default merge backend (default since 2.26): a rebase fires post-checkout ONCE, when moving onto the new base, with its third argument 1; then post-commit ONCE PER REPLAYED COMMIT; then post-rewrite once at the end. A commit --amend fires post-commit and then post-rewrite.

So post-commit — which cortex install --git-hooks already installs, and which reconciles — covers both the amend and the replay. There is no gap for a fourth hook to close. Even if there were, decisions.db is a derived cache and the reconcile is idempotent, so the next command repairs it.

Decided: do not install post-rewrite; move the item to "Explicitly not adopting" with the measurement rather than leaving it as a deferral someone will re-open.

This measurement also exposed an open defect, recorded as backlog item 15: shouldEmbed in git-hook.ts excludes post-checkout on the strength of the same wrong claim, so a fifty-commit rebase spawns fifty detached embed --missing processes through post-commit, each loading the embedding model. Excluding post-checkout is still right, but for the reason CLAUDE.md gives (a restored decision keeps its vector), not the reason the comment gives.
