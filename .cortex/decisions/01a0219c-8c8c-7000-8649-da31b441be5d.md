deriveLinks used to add every REPLACED_BY/ARCHIVED_BY source to the replaced set with no cycle check, and supersededTwice only noticed a target retired by two different files. So two branches that each superseded the other's decision — or one file naming its own id — merged cleanly and retired both decisions, removing them from search, get_context, prompt-hook and search_all_projects with a completely empty report. Decision files are immutable, so there was no undo except writing yet another decision.

Both facts are true, which is why this is dropped and reported rather than resolved: an edge whose target can reach its source again through the retirement graph goes into ReconcileReport.cyclic and is never inserted, leaving both decisions active until a human writes the one that settles it. Reachability is asked per edge over the retirement subgraph only — one node per decision, so the cost is nothing and the code is a BFS instead of Tarjan. A DEPENDS_ON cycle is deliberately left alone: it retires nothing, and get-impact.sql already bounds its own walk.

A self-edge of any kind is dropped by the same rule, and migration 008 adds CHECK (from_id <> to_id) to make one unrepresentable. That CHECK is why the drop cannot be optional: an edge reaching insertVersionedEdge would throw inside the reconcile transaction and roll the whole pass back, on every command, forever — a depends_on naming its own decision would have been enough.

Rejected: resolving the cycle by picking a winner (no fact says which), and reporting without dropping (the status would still be wrong on both sides).
