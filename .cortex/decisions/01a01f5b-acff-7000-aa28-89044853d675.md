Every staging path here is `${target}.${pid}.partial` — derived from the target, so anyone who can write to the directory can guess it — and it was written through a path, which follows a symlink sitting at it. In installBinary that is worse than an overwrite: chmod 0755 lands on the link's target and rename moves the symlink itself onto cortex. It crosses a privilege boundary wherever directory write is easier to get than file replacement (a group-writable /usr/local/bin, a shared CORTEX_INSTALL_DIR).

createStagingFile opens with "wx" (O_EXCL), which refuses a planted symlink outright, and both writers and the installer now go through it — one place that knows how a staging file is named and created.

O_EXCL gives up two things Bun.write did silently, so both are done deliberately in the retry: a missing parent directory is created (callers depend on that — the onnxruntime cache extracts into one), and a leftover staging file is unlinked and the open retried. The retry is safe where an overwrite would not be, because the second attempt is exclusive too: anything planted in between fails the open rather than being written through. Any other errno propagates.

installBinary additionally sweeps abandoned staging files before writing, since an upgrade killed between the download and the rename left one in the install directory forever. The pid in the name is what makes the sweep precise: only a pid the kernel answers ESRCH for is reclaimed, so an upgrade running beside this one is left alone, and no age heuristic is needed. The sweep is deliberately not applied to the general writers — the installer is the one directory a user's PATH points at.
