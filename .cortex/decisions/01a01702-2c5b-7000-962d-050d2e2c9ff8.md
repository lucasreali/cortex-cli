worker.ts used `extractorPromise ??= createExtractor()`, and ??= only reassigns on null or undefined — a rejected promise is neither. One transient DNS failure, a 503 from the model CDN, a half-written cache file or an unavailable wasm backend was therefore memoised for the life of the process. Over 200 decisions that means #1 fails and #2..#200 fail instantly with the identical stale message; inside the long-lived shared daemon one blip made every session on the machine see the same error with no self-healing.

RetainedLoad keeps the promise only once it fulfils and drops it on rejection, so the next caller retries. Exiting the worker on a load failure was considered and rejected: the error response is already sent, and tearing the process down would take the ledger's other in-flight requests with it for no gain.
