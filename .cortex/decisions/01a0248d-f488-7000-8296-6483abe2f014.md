replayStepsRemaining reads rebase-merge/git-rebase-todo and sequencer/todo to keep a rebase from spawning one detached embed per replayed commit. A todo left behind by a killed cherry-pick or an interrupted rebase is never cleaned up by anyone, and the guard read it as an operation in progress forever — so that repository's post-commit embed was permanently suppressed, invisibly.

The two mistakes are not symmetric, and that asymmetry is the whole rule. Answering "no replay" during a real one costs a handful of redundant background embeds, each idempotent. Answering "replay" when none is running costs the embed for good. So the guard is made to fail in the cheap direction: a todo whose mtime is older than an hour is read as wreckage.

Age is the signal because git rewrites the file on every step — no replay leaves it untouched for an hour between commits. A rebase paused overnight and resumed will spawn one extra embed per remaining commit, which is the price and is deliberately the cheap side. Rejected: keying on CHERRY_PICK_HEAD, which git removes before post-commit runs, and on the sequencer directory's existence, which is exactly what survives the crash.
