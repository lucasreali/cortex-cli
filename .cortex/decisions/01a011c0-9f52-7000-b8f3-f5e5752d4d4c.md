web-tree-sitter frees a syntax tree only through Tree.delete() and registers no FinalizationRegistry, so a tree left to the JS GC keeps its emscripten allocation — measured at roughly thirty times the parsed bytes — for the life of the process. TsxExtractor.extract now parses into a local, materializes symbols and imports, and deletes the tree in a finally block; both halves return plain objects, so nothing outlives it.

Measured here: 100 parses of a 41 KB file grew process external memory from 69 MB to 418 MB and stayed there after a forced GC; with the delete it is flat. The compiled binary peaked at 935 MB indexing an 18 MB repository. The MCP server is where this actually bites — the runtime is cached per project and every lazy reconcile added heap that was never given back, so a server open over an active repository grew without bound. tests/indexer/extractor.test.ts pins the flatness, because no other gate can see a leak.
