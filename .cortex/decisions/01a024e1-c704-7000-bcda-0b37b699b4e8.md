Nothing signed checksums.txt. A consumer verified a tarball against a file served by the same origin as the tarball, which detects corruption in transit but not substitution: whoever can replace the asset can replace the listing beside it. The trust root was TLS plus the integrity of one GitHub account.

Every release asset (and checksums.txt itself) is now attested with actions/attest-build-provenance, which binds the bytes to the workflow, commit and repository that produced them and is verified against Sigstore's transparency log rather than against github.com's file server. verify-darwin runs `gh attestation verify` on the published asset, so the instruction the README hands readers is exercised on every release before anyone follows it.

Signing with a project-held key (GPG, minisign) was rejected: it moves the trust root to a secret this repository would have to store, rotate and never leak, and a key in GitHub Actions secrets is protected by exactly the account integrity the attestation is meant to stop depending on.

install.sh is deliberately unchanged — it must run with curl and tar alone, and `gh` is not a dependency an installer may assume. The attestation is the stronger optional check, not the baseline one.
