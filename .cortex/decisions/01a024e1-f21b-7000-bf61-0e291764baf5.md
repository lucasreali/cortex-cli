Checksums built a Map from the listing, so a second line for the same asset silently won — last-wins. install.sh reads the same file with `awk '$2 == name { print $1 }'`, which prints every match, so its comparison fails on any duplicate, identical lines included.

The two verifiers must not disagree about which bytes a release names. Checksums now throws on any duplicate asset name at construction, matching install.sh's accidental fail-closed behaviour deliberately, and the throw propagates out of downloadRelease so an upgrade fails rather than installing an ambiguous asset. Resolving to the first line, or accepting duplicates that agree, were both rejected: an ambiguous listing is not a fact about a release.

scripts/package-release.ts asserts the same invariant before writing the file, so a name collision is found at build time instead of after upload.
