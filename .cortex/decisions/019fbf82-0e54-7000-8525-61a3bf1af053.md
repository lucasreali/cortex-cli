The timeout-and-dispose dance was written three times (queue.ts, embed-all.ts, the daemon), each carrying its own copy of the rationale. disposingOnTimeout in with-timeout.ts holds it once.

The asymmetry stays deliberate and is now stated where it belongs: semantic-search still does NOT dispose on timeout, so a model still loading after an idle-kill finishes for the next query instead of restarting, and FTS answers meanwhile.

IdleTimer replaces two implementations of the same object that shared a byte-identical clear and each declared their own 5-minute default. line-buffer.ts becomes ndjson.ts and gains encodeNdjson, because the write side was five copies of the same template literal facing the same reader.

A full NdjsonChannel over the socket and the pipe was considered and rejected: the daemon client reads push-style from a socket callback and the worker link reads pull-style from an async iterable, so the shared abstraction would be more adapter than saving.
