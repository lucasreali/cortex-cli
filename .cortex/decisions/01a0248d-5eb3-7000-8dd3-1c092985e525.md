--json was honoured on the happy paths and ignored on every error path — usage errors, "decision not found", an uninitialized project, a store that would not open — so a caller parsing stdout had to scrape a decorated sentence off stderr. src/cli/error-output.ts now owns both reportFailure and usageError, and every console.error(failure(...)) under src/cli calls it.

The mode is read from process.argv rather than threaded through the commands, because the failures that matter most happen where no parsed argument exists yet: the throw main.ts catches, requireInitialized, and the usage error parseArgs never got to produce. Threading a flag would have meant a parameter on every command signature that only the error path uses.

Which commands may answer in JSON is decided by USAGE, not by a second list: a usage line that mentions --json is the definition of a command that speaks it. That keeps `cortex init --json` — a typo — from being answered in a shape init never prints, and it means adding --json to a command cannot forget to teach its errors. usage.ts is therefore the USAGE table alone; usageError moved out because it is an error reporter, and leaving it there would have made usage.ts import error-output.ts, which imports usage.ts.
