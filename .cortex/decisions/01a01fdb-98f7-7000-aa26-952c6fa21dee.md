The code index was reconciled once per process. That is right for a command and wrong for the MCP server, which outlives many snapshots: a session writes a function, anchors a decision to it, and hasSymbol answers from the tree as it looked when the server started — so the model is told its anchor is wrong about code it just wrote.

There is still no file watcher. What replaces it is a freshness window: LazyCodeIndex re-checks once its last pass is older than RECHECK_AFTER_MS (5 s). The window is what keeps a burst of tool calls from walking the tree once each, and it is affordable because an unchanged incremental pass is a directory walk and a stat per file, not a parse — measured here at 35 ms warm against 590 ms cold over 286 files.

The re-check reuses the connection and the CodeIndexer it already has. A second indexer would reload the grammar and hold a second web-tree-sitter parser for the life of the process, which is the same leak class as the tree the extractor frees by hand.

Two invariants survive the change. A pass that throws closes the connection it was handed, because a failed pass is not cached and nothing could reach the handle afterwards. And only the pass that failed may clear the cached one — the identity check is what keeps a dispose racing an in-flight pass from dropping a live index and leaking it.

An in-flight pass is fresh by definition; that is what the infinite window encodes, and it is what makes concurrent callers share one reconcile.
