Two paths could not be driven end to end by the suite: cortex upgrade's install orchestration, which short-circuits on "this is a source checkout" before doing any work, and anything that spawns a private embedding worker (a git hook's detached embed, embed --rebuild), because loading the real model in bun test is not affordable.

Both are opened with an environment variable, and both take CORTEX_RELEASE_BASE_URL's rule rather than inventing one. CORTEX_UPGRADE_TARGET_PATH (upgradeTargetPath in release/installer.ts) names the file an upgrade may replace; CORTEX_EMBED_WORKER_PATH (embedWorkerCommand in embedding/subprocess-command.ts, which the daemon already read) names a script to spawn in place of the real worker. A compiled binary ignores both, decided by import.meta.url containing the $bunfs prefix, the one fact about this process an environment variable cannot forge.

The reason is identical in all three cases: a variable that chooses which program cortex downloads, executes or writes over would let anything able to set one — a cloned repo's .envrc, an MCP server's env block, a CI job — own every later cortex on the machine and every agent session that spawns it.

scripts/compiled-smoke.ts proves the compiled half, because whether this process is an installed binary is exactly what a suite that always runs from source cannot establish about itself: it embeds successfully with CORTEX_EMBED_WORKER_PATH pointing at a script that exits 1, beside the two origin refusals already there.

Rejected: reading the variables unconditionally, for the privilege reason above; and injecting collaborators instead, because the seam has to cross a process boundary — these paths are reachable only by spawning the CLI.
