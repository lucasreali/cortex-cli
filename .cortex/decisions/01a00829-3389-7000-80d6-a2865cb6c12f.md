graphify renders 16 per-host skill files from shared fragments plus a platforms.toml manifest and fails CI on drift. Evaluating that pattern for cortex split it in two, and the two halves got opposite verdicts.

Rejected — the generator. cortex has exactly one instruction body, CORTEX_INSTRUCTIONS_BODY, written verbatim to every target; the targets differ only in filename (CLAUDE.md / AGENTS.md / GEMINI.md in src/install/targets.ts), never in content. A generator here would be an identity function wrapped in a manifest. Nothing generated is committed to this repo either: init writes into the user's file, so there is no versioned artifact to drift.

Adopted — the check, because it had a live failure. The <!-- cortex:begin --> fence this repo dogfoods in its own CLAUDE.md still listed five MCP tools after search_all_projects made six, and nothing would ever have caught it.

The check asks INSTRUCTIONS_BLOCK.upsert what it WOULD write and asserts the action is "unchanged". That reuses the marker recipe in src/install/marked-block.ts rather than re-parsing markers in the test, and it turns each way of losing the block into a distinct diagnosis: "updated" is drift, "appended" is a missing begin marker, "skipped-malformed" is unpaired markers, "created" is an empty file. The load-bearing property is that a missing or malformed fence fails loudly — a drift check that passes vacuously when it cannot find its target is worse than no check.
