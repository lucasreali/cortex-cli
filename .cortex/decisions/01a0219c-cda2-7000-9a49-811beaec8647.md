readTextOrNull rethrew everything that was not ENOENT and parseAll had no try/catch, so one unreadable decision file propagated out of DecisionSync.ensure() — which every command runs. A directory named <id>.md gives EISDIR, a chmod 000 file gives EACCES, and either killed log, search, doctor and every MCP tool. Worse, runGitHook wraps everything in catch {}, so post-commit reconciliation silently stopped happening.

DecisionStore.read now answers { ok: false, reason } for anything that is not a readable regular file, and the file lands in ReconcileReport.malformed — present-but-unusable, never absent, exactly like a file that does not parse. The kind is checked with statSync before the bytes are read, so a directory reports "not a regular file" instead of an errno string and a fifo cannot block the reconcile for as long as nobody writes to it.

The directory listing is the one read that must not degrade to a value. Answering with the empty listing would mark every decision in the store absent, so DecisionListing is a discriminated result: on failure the reconcile reports the directory and changes nothing. listIds()/listUnparseableNames() were replaced by one list() call for the same reason — two accessors would each have to decide what an unreadable directory means, and only one of them could be right.

Two more things nothing else collects are reported through the same channel: a .partial staging file left by a process killed between the write and the rename (invisible to loading, invisible to git review, in a committed directory), and a filename whose id is not lowercase — the UUID regex dropped its /i flag because <ID>.MD and <id>.md are one decision on macOS and two on Linux.
